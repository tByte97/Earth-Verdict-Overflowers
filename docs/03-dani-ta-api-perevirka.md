# 03 · Дані та API: що реально працює

Тут лише те, що можна підключити до продукту. Кожен рядок позначено: **перевірено** (я зробив
запит 14.11.2026 і бачив відповідь) або **з документації** (прочитав, але не запускав).

## Матриця доступу

| Джерело | Ключ | З браузера (CORS) | Відповідь | Геометрія | Стан |
|---|---|---|---|---|---|
| NASA POWER | не потрібен | так | миттєва, JSON | точка або регіон ≤ 10°×10° | перевірено |
| NOAA NCEI Access Data Service | не потрібен | так | миттєва, JSON/CSV | станція | перевірено |
| Giovanni: список змінних | не потрібен | не перевіряв | миттєва, JSON | — | перевірено |
| Giovanni: ряд для точки | **токен Earthdata** | лише через бекенд | CSV за секунди (за офіційним ноутбуком) | точка | відмова без токена перевірена, сам запит ні |
| Giovanni: усереднення за площею | **токен Earthdata** | лише через бекенд | CSV, **завдання в черзі** (NASA Harmony) | прямокутник | прочитано офіційний ноутбук, не запускав |
| AppEEARS API | логін Earthdata → токен | лише через бекенд | **черга завдань** | точки або полігон | каталог перевірено, завдання ні |
| Hydrology Data Rods (старий) | — | — | — | — | **закрито**, перевірено |
| Giovanni (вебінтерфейс) | вхід для повного доступу | — | ручний експорт CSV | прямокутник або форма | не перевіряв |
| KNMI Climate Explorer | перевірка «я людина» | — | ручний експорт | точка, регіон, країна | не перевіряв |

Висновок для архітектури: токен Earthdata не можна тримати у фронтенді, тож потрібен
бекенд-проксі з кешем. Це збігається з планом на FastAPI.

## Як названі в челенджі місії лягають на джерела

| Назване в челенджі | Де взяти | Приклади змінних | Роки |
|---|---|---|---|
| **MERRA-2** | NASA POWER; Giovanni API (`M2IMNXASM`, місячні) | T2M, опади, волога ґрунту, вітер, аерозолі | 1980 → зараз |
| **GLDAS** | Giovanni API (`GLDAS_NOAH025_M`) | евапотранспірація, стік, волога й температура ґрунту, сніг | v2.0: 1948–2014; v2.1: 2000 → зараз |
| **GPM** | Giovanni API (`GPM_3IMERGM`, місячні) | опади | 1998 → вересень 2025 |
| **AIRS** | Giovanni API (`AIRS3STM`, місячні) | температура повітря й поверхні, водяна пара, озон, хмарність, вихідне випромінювання | 2002 → зараз |
| **OMI** | Giovanni API (`OMNO2d`, `OMSO2e`, `OMTO3d`, `OMAERUVd`, `OMUVBd`) | NO₂, SO₂, озон, аерозольний індекс, УФ-індекс | 2004 → зараз |
| **MODIS** | AppEEARS (суходіл); Giovanni, лише вебінтерфейс (атмосфера, океан) | NDVI, температура поверхні, сніг, вигорілі площі | 2000 → зараз |

Роки початку для GPM, GLDAS, AIRS, OMI і MERRA-2 я звірив із каталогом метаданих NASA (CMR).
Роки MODIS наведено з каталогу AppEEARS.

Обережно з GLDAS: версії 2.0 і 2.1 використовують різні вхідні дані. Якщо просто склеїти їх в
один ряд, на стику з'явиться штучний стрибок, який тест сприйме за тренд.

## Giovanni Time Series API

Це нова заміна Data Rods. Дає ряд для однієї точки у форматі CSV.

Список змінних відкритий, **867 штук** (перевірено):

```
GET https://api.giovanni.earthdata.nasa.gov/configured-variables/
```

Запит ряду (з документації GES DISC):

```
GET https://api.giovanni.earthdata.nasa.gov/timeseries
      ?data=GPM_3IMERGM_07_precipitation
      &location=[50.4,30.5]              # широта, довгота
      &time=2000-06-01T00:00:00/2025-10-31T00:00:00
      &version=07
Authorization: Bearer <токен Earthdata Login>
```

У командному рядку параметри треба URL-кодувати. Без токена сервіс відповідає
`403 Bad or missing token` (перевірено). Адреса `…/proxy-timeseries` призначена лише для
браузера: вона спершу веде на сторінку входу.

Що з'ясувалося з офіційних ноутбуків NASA (`nasa/gesdisc-tutorials`):

- параметр `version` необов'язковий: у ноутбуці його немає;
- **швидкість**: 20.75 року 3-годинних даних (близько 60 000 значень) за 5.8 секунди;
- є **усереднення за прямокутником** через бібліотеку `harmony-py`
  (`average="area"`, `format="text/csv"`) і **карта середнього за період**
  (`average="time"`, `format="image/tiff"`). Це завдання в черзі, а не миттєвий запит;
- є **місячна квота обчислень**: `GET /quota` повертає частку використаного;
- відповідь починається з рядків метаданих (назва, одиниці, значення пропуску, координати
  центру клітинки), далі порожній рядок і таблиця `Timestamp (UTC),Data`.

Повний розбір у `resursy/A1-giovanni-time-series-api.md`.

- справжній час відповіді з нашої мережі;
- скільки квоти з'їдає один запит для точки;
- скільки триває завдання на усереднення за площею;
- термін дії токена (ноутбук каже 24 години, документація Earthdata 60 днів).

## NOAA NCEI Access Data Service

Станційні вимірювання. Працює без ключа (перевірено):

```
GET https://www.ncei.noaa.gov/access/services/data/v1
      ?dataset=global-summary-of-the-month
      &stations=UPM00033345
      &startDate=1881-01-01&endDate=2026-12-31
      &dataTypes=TAVG,TMAX,TMIN,PRCP
      &format=json&units=metric
```

Пошук станцій у прямокутнику (перевірено, параметр `bbox` у порядку північ, захід, південь,
схід):

```
GET https://www.ncei.noaa.gov/access/services/search/v1/data
      ?dataset=global-summary-of-the-month
      &bbox=52.4,22.1,44.3,40.2
      &startDate=1950-01-01&endDate=2025-12-31&limit=5
```

Результати:

- Київ: 1586 місяців, 1881-01 → 2025-07.
- Навколо України 292 станції. Найчастіші типи даних: `PRCP` (289), `TMAX` і `TMIN` (257),
  `TAVG` (247), сніг `DSND` (123).
- `global-summary-of-the-year` для Києва закінчується 2005 роком, тому брати місячний набір.

Класичний API CDO v2 (`/cdo-web/api/v2/`) потребує токен, який надсилають на пошту, і має
ліміти 5 запитів на секунду та 10 000 на добу. Це з документації, не перевіряв. Сервіс вище
його замінює.

## NASA POWER

Джерело прототипу. У списку ресурсів челенджу його немає, але це дані NASA (MERRA-2 і CERES).

```
GET https://power.larc.nasa.gov/api/temporal/monthly/point
      ?parameters=T2M&community=AG&longitude=30.5&latitude=50.4
      &start=1981&end=2025&format=JSON
```

Працює, ключ не потрібен, CORS `*` (перевірено). Обмеження з прототипу: у регіональному запиті
один параметр і не більше 10°×10°; волога ґрунту округлена до 0.01.

## AppEEARS

Каталог продуктів відкритий (перевірено, 193 продукти):

```
GET https://appeears.earthdatacloud.nasa.gov/api/product
```

Далі, з документації: `POST /api/login` з логіном і паролем Earthdata повертає токен;
`POST /api/task` створює завдання (тип `point` або `area`, перелік шарів, дати, координати);
результат забирається через `/api/bundle/{task_id}`. Координати лише в географічній проєкції.
Час виконання завдання невідомий.

## Giovanni: глосарій як готовий вміст

`giovanni.gsfc.nasa.gov/giovanni/doc/glossary/Giovanni_Variable_Definitions_Glossary.html`:
129 термінів, сторінка відкрита без входу, близько 1400 рядків тексту. Приклад стилю: «Total
Evapotranspiration is the sum of evaporation and plant transpiration…». Тексти наукові, для
школяра їх треба спрощувати, але це офіційне джерело NASA, на яке можна послатися.

## Що це означає для вибору джерел

1. **Основа лишається на NASA POWER**: миттєво, без ключа, є карта по сітці.
2. **Giovanni API додає названі місії** (OMI, AIRS, GPM, GLDAS, GRACE) через бекенд. Ряд для
   точки можна брати наживо. Ряд для регіону рахувати заздалегідь. Карту тренду по сітці з
   тисяч точкових запитів робити не можна через місячну квоту.
3. **NOAA додає прямі вимірювання** і найдовший ряд. Підключається за годину.
4. **AppEEARS** лише для справ, порахованих заздалегідь.
